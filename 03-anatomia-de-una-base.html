3  Anatomía de una base

TipLa idea en una línea

Una base no es una lista de números: es una tabla donde cada fila representa un caso, cada columna una variable y cada celda una medición que tiene que poder interpretarse.

3.1 La tabla que está detrás de cualquier análisis

Abrís una base y ves filas, columnas y valores. Parece obvio, pero el análisis se complica cuando no podés contestar qué representa cada una de esas cosas. La regla es simple:

  • una fila es un caso: una persona, una escuela, una respuesta o una medición, según tu pregunta;
  • una columna es una variable: una característica que puede cambiar de un caso a otro;
  • una celda es el valor de esa variable para ese caso.

En la encuesta ficticia que vamos a usar durante el libro, cada fila corresponde a un estudiante. horas_estudio es una columna y el número de horas semanales de una persona es una celda. Si cada fila mezclara estudiantes, materias o momentos de medición sin avisarlo, no tendrías una base lista para analizar: tendrías una tabla difícil de descifrar.

id turno horas_estudio procrastinacion aprobo_parcial
001 mañana 8 31 sí
002 noche 3 42 no
003 tarde 6 27 sí

No hace falta memorizar esa tabla. Sí hace falta poder leerla en voz alta: “el caso 002 cursa de noche, estudia tres horas semanales, tiene un puntaje de procrastinación de 42 y no aprobó el parcial”. Si no podés hacer esa traducción, todavía no sabés qué hay en la base.

3.2 Antes de analizar: tres preguntas por columna

Para cada variable, respondé estas preguntas antes de abrir Analyses:

  1. ¿Qué mide o clasifica? turno clasifica el horario de cursada; horas_estudio mide una cantidad.
  2. ¿Qué valores puede tomar y qué significan? “Sí” y “no” son claros; 1 y 2 no lo son si nadie dejó anotado cuál es cuál.
  3. ¿Qué papel cumple en mi pregunta? Puede ser una variable de agrupamiento, de resultado o simplemente un identificador que no vas a analizar.

La tercera pregunta conecta esta base con el plan de análisis del Capítulo 2. Una misma variable puede ser útil en una tabla y no entrar en un test; no todas las columnas tienen que ser protagonistas.

3.3 El número no alcanza para saber qué tipo de variable es

Un número puede ser una cantidad, una etiqueta o un código. Por eso 1 = mañana, 2 = tarde y 3 = noche no convierten al turno en una variable continua: sumar esos códigos o calcular su promedio no tiene sentido. Antes de hacer cuentas, preguntate si la distancia entre los valores representa algo real.

En jamovi conviene separar dos decisiones. El tipo de dato describe cómo se guarda el valor: entero, decimal o texto. El nivel de medida indica cómo debe tratarse en el análisis: nominal, ordinal, continua o ID. Al importar una base, jamovi hace una estimación automática; revisarla es parte de preparar la base, no un detalle técnico.

Nivel de medida Qué representa Ejemplo Qué no conviene hacer
Nominal Categorías sin orden turno: mañana, tarde, noche Promediar las categorías.
Ordinal Categorías con orden, pero sin distancias conocidas Acuerdo: nada, poco, bastante, mucho Suponer que cada salto vale lo mismo.
Continua Cantidades donde las diferencias son interpretables horas_estudio, procrastinacion Convertirla en grupos sin una razón.
ID Identifica un caso id Usarla como variable de resultado o agrupamiento.

La distinción no es un examen de definiciones. Te permite anticipar qué opciones aparecerán en jamovi y qué resumen tiene sentido pedir. Para una variable nominal, querés frecuencias; para una continua, una media o una mediana puede ser útil. Esa decisión la vamos a usar en el Capítulo 7.

3.4 Cómo mirarlo en jamovi

En la planilla de jamovi, cada encabezado de columna muestra un símbolo que resume el nivel de medida. Si algo no coincide con tu variable, abrí el editor de variables: podés hacerlo desde Data → Setup o con doble clic sobre el encabezado. Ahí revisás el nombre, la etiqueta, el tipo de dato, el nivel de medida y los valores de las categorías.

No cambies una columna a “continua” para forzar un análisis que querés hacer. Primero definí la variable; después elegí la herramienta que respeta esa definición. Si la base está bien armada, jamovi te ayuda a no ofrecerte combinaciones sin sentido. Si está mal armada, puede producir un número igual de prolijo y mucho menos defendible.

3.5 La base de este libro

Durante los próximos capítulos vamos a trabajar con una encuesta sintética de 72 estudiantes. Esta es la anatomía que debería tener su versión limpia:

Variable Nivel de medida Papel habitual
id ID Identifica cada caso; no se analiza.
edad Continua Describe la muestra.
turno Nominal Agrupa para comparar tres turnos.
horas_trabajo Continua Permite definir el criterio de trabajo.
trabaja Nominal Agrupa: sí = 10 o más horas semanales.
horas_estudio Continua Se relaciona con procrastinación.
procrastinacion Continua Variable de resultado en varias preguntas.
organizacion Continua Se compara con un valor de referencia.
aprobo_parcial Nominal Se asocia con otras categorías.

Fijate que una base bien organizada ya deja ver preguntas posibles. Pero “posible” no significa “interesante”: la pregunta viene primero. La base tiene que permitir responderla sin que tengas que redefinir todo cuando los datos ya están cargados.

3.6 Autochequeo

Antes de seguir, elegí una base propia y comprobá lo siguiente:

  1. ¿Podés decir qué representa una fila sin usar la palabra “dato”?
  2. ¿Cada columna tiene un nombre corto y una definición que otra persona entendería?
  3. ¿Hay códigos numéricos que podrían confundirse con cantidades?
  4. ¿Marcaste los identificadores para no analizarlos por accidente?

Si una respuesta es “no”, todavía no necesitás un test: necesitás ordenar la base. El próximo capítulo te da el documento para hacerlo.
